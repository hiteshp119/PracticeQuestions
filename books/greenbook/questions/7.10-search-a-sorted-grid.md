## Problem

You have an $n\times n$ grid of numbers. Each row increases from left to right and each column increases from top to bottom. Design an algorithm to find a given number $x$, and give its complexity.

## Solution

1. Start at the top-right element $A_{1,n}$: it's the largest in its row and the smallest in its column.
2. At $(i,j)$:
   - $A_{ij} = x$: found.
   - $A_{ij} < x$: everything left of it in row $i$ is smaller still, so row $i$ is out: $i\leftarrow i+1$.
   - $A_{ij} > x$: everything below it in column $j$ is larger still, so column $j$ is out: $j\leftarrow j-1$.
3. Each step deletes a row or a column; stop when you leave the grid: at most $2n - 1$ steps, $O(n)$.
```
i, j = 0, n - 1
while i < n and j >= 0:
    if A[i][j] == x: return (i, j)
    if A[i][j] < x: i += 1
    else: j -= 1
return None
```
(The bottom-left corner works symmetrically. $O(n)$ is optimal: the anti-diagonal could hold $x$ anywhere.)

## Intuition

**Naive approach.** Binary search each row: $O(n\log n)$; or start at the top-left.

**Why it fails.** At the top-left, both moves (right or down) increase the value, so a comparison can't tell you which way to go.

**The trick.** Choose a starting point where the two directions disagree (one up, one down). Then every comparison prunes a whole line.
