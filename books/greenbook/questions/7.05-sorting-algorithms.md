## Problem

Explain three algorithms for sorting $n$ distinct values and analyse their complexity.

## Solution

1. **Insertion sort.** Keep $A[1..i-1]$ sorted; insert $A_i$ by shifting larger elements right. Step $i$ costs up to $i - 1$ comparisons ($\frac{i}{2}$ on average):
$$\begin{aligned}W(n) &= \textstyle\sum i = \Theta(n^2),\\ A(n) &= \textstyle\sum\tfrac i2 = \Theta(n^2).\end{aligned}$$
Fast for small or nearly sorted arrays.
2. **Merge sort.** Split in halves, sort each recursively, merge in $\Theta(n)$:
$$T(n) = 2T(n/2) + \Theta(n).$$
Master theorem ($a = b = 2$, $f = \Theta(n^{\log_22})$): $T(n) = \Theta(n\log n)$, best = average = worst. Needs $O(n)$ extra memory; stable.
3. **Quicksort.** Pick a pivot, partition into smaller / larger, recurse.
   - Worst case: pivot is always the min or max (first-element pivot on sorted input): $\sum(n - i) = \Theta(n^2)$.
   - Average (random order or random pivot): items ranked $p < q$ are compared iff the first pivot chosen from ranks $p..q$ is $p$ or $q$:
$$\begin{aligned}E[\text{comparisons}] &= \sum_{p<q}\frac{2}{q-p+1}\\ &\approx 2n\ln n = \Theta(n\log n).\end{aligned}$$
In practice often the fastest (in place, cache friendly).

## Intuition

**Naive approach.** "Quicksort is $O(n\log n)$."

**Why it fails.** Only on average; adversarial or sorted input with a fixed pivot is quadratic.

**The trick.** Divide and conquer: halving the problem $\log_2n$ times with linear work per level gives $n\log n$. Any comparison sort needs $\log_2 n!\approx n\log_2n$ comparisons, so merge sort is asymptotically optimal.
