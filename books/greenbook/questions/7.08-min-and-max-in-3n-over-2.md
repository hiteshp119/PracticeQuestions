## Problem

Develop an algorithm to find both the minimum and the maximum of $n$ numbers using no more than about $\frac{3n}{2}$ comparisons. How many comparisons does it use for $n = 100$?

## Solution

1. Naive: $n - 1$ comparisons for the min, $n - 1$ for the max: $2n - 2$.
2. **Pairs.** Compare $a_1$ with $a_2$, $a_3$ with $a_4$, …: $\frac n2$ comparisons. Put each smaller element in group $L$, each larger in group $H$.
3. The minimum is in $L$, the maximum in $H$ (each element lost or won at least once). Scan each: $\frac n2 - 1$ comparisons each.
4. Total for even $n$:
$$\frac n2 + 2\Big(\frac n2 - 1\Big) = \frac{3n}{2} - 2 = 148\quad(n = 100).$$
For odd $n$, set the leftover element aside and compare it with both final candidates: $\lceil 3n/2\rceil - 2$ in general.

This is optimal: every element except the eventual min must lose once and every element except the max must win once; an adversary argument shows $\lceil 3n/2\rceil - 2$ comparisons are necessary.

## Intuition

**Naive approach.** Two independent scans.

**Why it fails.** Comparing $x$ with the current max tells you nothing new about the min.

**The trick.** Make each comparison do double duty: one comparison decides which tournament (min or max) each of two elements is eligible for.
