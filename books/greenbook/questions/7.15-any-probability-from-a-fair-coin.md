## Problem

You have a fair coin. Design a simple game so that your probability of winning is $p$, for any given $0 < p < 1$.

## Solution

1. Binary expansion: $p = \sum_{i\ge1}p_i2^{-i}$, $p_i\in\{0,1\}$.
2. Toss the coin repeatedly; let $s_i = 1$ for heads, $0$ for tails. $U = 0.s_1s_2s_3\ldots_2$ is uniform on $[0,1]$.
3. Compare digit by digit. At the first $i$ with $s_i\ne p_i$:
   - $s_i = 0 < p_i = 1$: $U < p$, **win**;
   - $s_i = 1 > p_i = 0$: $U > p$, **lose**.
4. $P(\text{win}) = P(U < p) = p$. Each toss stops the game with probability $\frac12$, so the expected number of tosses is 2. (If $p$ has a finite expansion and all its digits are matched, count it as a loss; that event has probability 0 in the limit, and for the finite version it makes the probability exact: e.g. $p = 0.01_2 = \frac14$ wins only on "TT".)

## Intuition

**Naive approach.** Approximate $p$ by a fraction $\frac{k}{2^n}$ and toss $n$ coins.

**Why it fails.** Only exact for dyadic $p$, and wastes tosses.

**The trick.** A fair coin is a source of random bits, i.e. of a uniform number. Generate only as many bits as needed to decide $U < p$ (lazy evaluation).
